A complete example

A benchmark is a specification plus implementations of it. Here the specification is alu_k3_8t: an ALU for ternary numbers with 8 digits (0 to 38−1 = 6560) and six operations that wrap around modulo 38. To add your implementation of it, you upload two files:

  1. manifest.json says what it is: the specification (k_value 3 and bitwidth 8 give the name alu_k3_8t), your source files and their language, and who you are.
  2. The source file does the computing: a function alu_exec(a, b, op) that returns the result and the flags Z, N, C. Our tests call it directly (interfaces for every language).
  3. Its own tests print one line each: Test 1: ADD A=0 B=0 -> R=0 Z=1 N=0 C=0. Every line is recomputed with the reference model.

      What the manifest needs
      • module_type, k_value, bitwidth, operations — define the spec; the name is derived (alu_k3_8t).
      • files[] — filename + language for every uploaded source file.
      • source — human-authored, llm-generated (then generator.model is required) or reference.
      • submitter — name, e-mail, affiliation; shown as provenance.
      • license — must be CC-BY-4.0: by submitting you agree to publish under this license.

      Test output must follow Test N: OP A=.. B=.. -> R=.. Z=.. N=.. C=.. so the golden-model comparison can read it. The manifest is validated in your browser before upload.
