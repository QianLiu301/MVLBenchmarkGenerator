Benchmark format v1.0

Every entry in the library is a specification (what is computed) with one or more implementations (how it is computed, in a given language). Both are described by a small set of conventions so that entries can be compared, verified and cited uniformly. When you reference the format in a paper, please state the version: MVL Benchmark Library format v1.0.

1. Naming

Specifications are identified by a stable name derived from their parameters:

  • alu_k3_8t — ALU, radix k = 3, 8 digits (trits)
  • regfile_k3_8t_r16 — register file with 16 registers
  • cpu_k3_8t_p5 — 5-stage processor

Implementation files carry the specification name and the language extension: alu_k3_8t.c, .py, .v, .vhd.

2. Algebraic structure

The structure is fixed by k: GF(p) for prime k, GF(pⁿ) for prime powers (digit-wise field arithmetic), and the integer ring Z/kZ otherwise. Operands are integers in 0 … kⁿ − 1; results are reduced modulo kⁿ. Each benchmark page lists the exact definition of every operation and flag.

3. Test output

Implementations print their self-test vectors in one line per vector so the golden-model comparison can read them:

Test  1: ADD A=0 B=0 -> R=0 Z=1 N=0 C=0
Test  2: SUB A=6560 B=1 -> R=6559 Z=0 N=1 C=0

Accepted variants: result= instead of R=, lower-case keys, and a numeric OP= field (0 = ADD … 5 = DEC). Flags Z / N / C are optional but compared when present.

4. Manifest (manifest.json)

Submissions bundle their files with a manifest. The schema is published at /submit/manifest-schema.json; a template is available on the Submit page.

5. Verification record

Each published implementation stores: simulation result (compiles and runs), golden-model result over the self-reported vectors and over N injected golden vectors with a fixed seed (random(N=50, seed=42)), the toolchain versions used, the golden-model version, the SHA-256 of the file and the simulator log. These are shown on the benchmark page and exported in spec.json.

6. Download archives

Per-benchmark and library-wide archives contain <name>/spec.json, the implementation files, LICENSE.txt (CC BY 4.0) and CITATION.bib. When several implementations share a language, the file name carries the source and id, e.g. alu_k3_8t_deepseek_12.c.
