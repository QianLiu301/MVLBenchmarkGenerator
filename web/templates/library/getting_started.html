Getting started

Every benchmark is a specification (what is computed) with implementations of it in C, Python, Verilog and VHDL. This page shows how to get the files, what is inside them, how to run one, and how to use the library from a script.

1. Get the files

  • One benchmark — open its page, for example {{ slug }}, and use Download all files, or copy a single implementation from the page.
  • A selection — Download by selection lets you pick radix, digits, language and verification status and returns one archive.
  • Everything — the full library archive, or the citable snapshot on Zenodo.
  • From a script — the JSON API.

2. What is in an archive

{{ slug }}/

  {{ slug }}.c          implementations; several per language carry source and id
  {{ slug }}.py           in the name, e.g. {{ slug }}_gemini_106.v
  {{ slug }}.v
  {{ slug }}.vhd
LICENSE.txt            CC BY 4.0

3. Run an implementation

Each file is self-contained and prints its own test vectors in the format convention (Test N: OP A=… B=… -> R=… Z=… N=… C=…), so a run is a quick sanity check that your toolchain agrees with ours. 

# C
gcc -O2 -o alu {{ slug }}.c && ./alu

# Python
python {{ slug }}.py

# Verilog (Icarus)
iverilog -o alu.vvp {{ slug }}.v && vvp alu.vvp

# VHDL (GHDL)
ghdl -a --std=08 {{ slug }}.vhd
ghdl -e --std=08 {{ entity }}_tb
ghdl -r --std=08 {{ entity }}_tb --stop-time=10ms

4. Use one as a device under test

The HDL entries expose a fixed interface, described in the format, section 4: an entity or module mvl_alu_<k>_<n>bit with clk, rst, a, b, opcode[3:0], result, zero, negative, carry; operands are the integer value of the word, opcodes are 0 = ADD, 1 = SUB, 2 = MUL, 3 = NEG, 4 = INC, 5 = DEC. Replace the testbench with your own and drive the design directly — that is exactly what our verification does.

The C and Python entries expose alu_exec(a, b, op) returning the result and the Z/N/C flags, so they can serve as a software reference next to your hardware.

5. Know what the verification means

A teal badge means the file matched the independent reference model on every vector, both the ones it prints itself and injected golden vectors (all operand pairs when kn ≤ 256, otherwise 50 seeded random pairs plus edge cases). The record on each entry lists the tool versions, the vector count and the seed, so a run can be repeated. Implementations that failed are kept when they come from the project's own LLM pipeline — see generation models — and are never presented as correct.

6. Cite what you use

Files are CC BY 4.0: use them anywhere, including commercially, as long as you give credit. The Cite page has the BibTeX for the paper and for the archived data release; each benchmark page carries the same entry with its permanent URL.

Contribute

Have an implementation, a new specification, or found a mistake? The submission page takes a manifest plus your files and runs them through the same pipeline; the review process states exactly what passes. Corrections to the reference model are welcome and are versioned publicly.
