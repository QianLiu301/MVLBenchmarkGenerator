About the MVL Benchmark Library

The MVL Benchmark Library is an online resource for benchmarks in the domain of multi-valued logic (MVL) design and verification. It provides a database of benchmark specifications — arithmetic-logic units, register files and processors defined over Z/kⁿZ (radix-k integer arithmetic) and GF(q)[x]/(xⁿ) (Galois-field polynomial arithmetic) — together with reference implementations in C, Python, Verilog and VHDL, all given in a common benchmark format.

Every implementation is compiled, simulated and compared digit-wise against an independent golden model before publication. Each entry carries its own verification record — test strategy, toolchain versions, random seed and file checksums — so that results can be reproduced.

The library is maintained by the Group of Computer Architecture (AGRA) at the University of Bremen and is open to contributions from the MVL community. Whether you design ternary arithmetic, study Galois-field hardware or evaluate verification tools, we invite you to browse, download and contribute benchmarks. Submissions pass an automated review pipeline followed by maintainer approval; new benchmarks can also be derived with our LLM-based generator.

What makes an entry

  • Specification — identified by a stable name such as alu_k3_8t (module, radix, digits). It fixes the algebraic structure: the ring Z/kⁿZ (radix-k integer arithmetic with carry) for k = 2, 3, 5, 6, 7 …, and the ring GF(q)[x]/(xⁿ) (digit-wise Galois-field arithmetic) when k = q is a prime power such as 4. The exact definitions and the reference model are in the format.
  • Implementation — one source file realising the specification. Several implementations may exist per language, e.g. produced by different LLMs, so that models can be compared on identical specifications.
  • Verification record — the implementation is compiled and simulated (gcc, CPython, Icarus Verilog, GHDL); every test vector it prints is compared digit-wise with an independent, deterministic golden model, and a second run injects golden vectors (all operand pairs for small ranges, otherwise a fixed seed). Only the result is stored; nothing is hand-edited. The pass and rejection rules are on the review process page.

Format

Naming, the manifest, the test-output convention and the verification record are specified in the benchmark format v1.0. Contributors are listed on the Acknowledgements page, and the pass rates of the generation models by language and family on the Models page.
